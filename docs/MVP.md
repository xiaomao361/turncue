# 0.2 原型验证计划

## 产品边界

TurnCue 提供的是路线认知，不是逐米导航：先告诉人大方向、主要通道、能确认位置的地标，以及到关键位置后怎么转。完整道路细节交给 Apple 地图。

## 已实施的顺序

1. 用 `RouteSketch → RouteLeg → LandmarkAnchor` 代替逐转弯模型。
2. 将 MapKit 原始步骤按显著转向、主干道、桥梁/环路和间距压缩，结果最多 7 段。
3. 在真实地图底图上绘制完整路线，但只标记少量关键节点；节点下方补充方向、估算距离、地标和决策。
4. 预览与跟随共用同一屏、同一数据；定位或手动动作只推进当前段。
5. 搜索时先提供补全建议，结果只突出最近的推荐地点，其余折叠；另有扩大范围和地图选点。
6. 交通方式默认按距离推荐；选中目的地后允许主动选择步行、驾车或骑行，草图标题显示实际采用的方式。
7. 提供“在 Apple 地图中查看”，传递起点、终点和交通方式。
8. 节点优先以真实地标命名，其次采用主路或路口名称；轻点后显示“怎么到这里”和“到达以后”。
9. 右上角菜单的“保存或分享路线图”生成包含地图与节点图例的静态图片，再由系统面板保存或分享。
10. 搜索和路线生成可取消；定位请求有超时退路，拒绝权限后可由用户打开设置。
11. 跟随可暂停、继续和退回；最终到达由用户明确确认，定位接近终点不会自动完成。

## 手机测试重点

短路线和熟悉的长路线各试一次，观察：

- 推荐目的地是否就是想去的那个；不是时能否快速修正。
- 3–7 个节点能否在十秒内建立整体方向感。
- 地标是否真实、显眼，并且出现在做决定之前。
- 估算距离是否足以判断“走一小段”还是“走很久”。
- 切换跟随状态后，仍能看见整张路线，而不是只剩一个转弯。
- 地图是否一眼能看出整体走向，同时没有普通导航图那么拥挤。
- 节点名称是否足以成为一段路的独立目标，而不是仍需盯着路线细节。

## 尚未证明

- 地标在现实视野中的可见性与道路哪一侧。
- 偏航检测、自动重算、后台导航和锁屏提示。
- MapKit 在不同城市对骑行路线的覆盖。
- VoiceOver 与大字体的真机人工验收。
